# Security Roadmap

Outstanding security work, and what has already been done. This file is a
record of **known gaps**, not a claim of clearance. Nothing here has been
security-audited end to end; the absence of a tracked item is not evidence that
the code is correct.

Last verified against `bde083a` (see [Re-verifying the counts](#re-verifying-the-counts)).

## Scope: what is done vs. what is outstanding

| Area | State |

### Completed: F35–F41

Closed the known DOM XSS sinks and the unvalidated stored-input paths:

- Shared escaping and URL helpers in `static/js/dom-safety.js`
  (`escapeText`, `escapeAttr`, `tmdbImageUrl`, `safeInternalUrl`,
  `safeImageUrlFromHosts`), loaded before the content block in
  `templates/base.html`.
- Username validation at both registration paths (`utils/username_policy.py`).
- TMDb image URLs pinned to `image.tmdb.org`; off-host poster and still
  requests rejected at render time.
- Server-side list-cover validation (`utils/cover_image_policy.py`) at write
  time **and** render time, with the server and browser layers held in
  agreement by a shared edge-case corpus.
- `KNOWN_OPEN` is empty and `KNOWN_OPEN_TOTAL = 0`. That is a build-failing
  ratchet, not a claim that no sink exists anywhere.

**CSP was deliberately not touched by that work.** `app.py` is unmodified
against its pre-F35 state, so the policy below is still exactly what shipped
before the remediation began.

## Outstanding: Content Security Policy hardening

### Current policy

`app.py:113` defines `_CSP`, applied to every response at `app.py:226`:

```
default-src 'self';
script-src  'self' 'unsafe-inline' cdn.tailwindcss.com cdn.jsdelivr.net cdnjs.cloudflare.com;
style-src   'self' 'unsafe-inline' cdn.tailwindcss.com cdn.jsdelivr.net cdnjs.cloudflare.com fonts.googleapis.com;
font-src    'self' fonts.gstatic.com cdnjs.cloudflare.com;
img-src     'self' data: blob: https: via.placeholder.com;
frame-src   www.youtube.com youtube.com www.vidking.net vidking.net
            www.rivestream.app rivestream.app vidy.st www.vidy.st 1embed.cc;
connect-src 'self';
```

`'unsafe-inline'` in `script-src` means an injected `<script>` block executes.
That is the single largest remaining gap, and it is why the F35–F41 work —
which fixes sinks one at a time — is defence in depth rather than a fix.

| # | Item | Count | Where |

| 2 | Inline `on*=` handler attributes in served markup | **62** | 15 templates |
| 3 | Handlers generated by JS at runtime | **39** | 8 templates + 2 JS files |
| 4 | CDN `<script src>` without SRI | **32** | 27 files, 2 hosts |
| 5 | Tests asserting the CSP header | **0** | — |

Detail:

- **Item 2** breaks down as `onclick` 45, `onerror` 17. The `onerror` cases are
  image-placeholder fallbacks; the heaviest files are `watch_tv.html` (10),
  `my_lists.html` (7), `watch_movie.html` (7).
- **Item 3** is 31 inside template `<script>` blocks plus 8 in
  `static/js/tv-tracker.js` (6) and `static/js/activity-feed.js` (2).
  Commented-out examples of the *old* inline handlers F21 already removed were
  excluded.
- **Item 4** is `cdn.tailwindcss.com` ×26 and `cdn.jsdelivr.net` ×6, across 6
  distinct URLs. Two of those are the same library at different pins
  (`chart.js` unversioned, and `chart.js@4.4.0`).
- Items 2 and 3 both need `'unsafe-inline'`: **101 inline handlers** in total.

### Work items

Seven items, listed in dependency order rather than by convenience — each
names what must be true before the next can start. Nothing here is started.

**1. Migrate inline event handlers to `addEventListener` or delegated
handlers.** *Prerequisite for item 7.* 101 sites. Several already use the
delegated-listener pattern F21 introduced (`my-services.js`,
`where-to-watch.js`), so the destination pattern exists in-tree. Delete the
handler attribute, bind a listener after insertion.

**2. Extract inline `<script>` to static files where practical, or introduce
per-response CSP nonces or hashes.** *Prerequisite for item 7.* 45 blocks.
Nonces require generating a per-request value, adding it to every `<script>`
tag, and threading it into `_CSP` — so `app.py` must change. That collides with
`test_schema_guard_source_is_untouched_by_f20`, which asserts
`git diff --quiet HEAD -- utils/schema_guard.py app.py`: any deliberate
`app.py` edit turns that test red until the guard is updated on purpose. Do
not relax it quietly to get a green build. Hashes require a build step that
rewrites content. Extraction is the least invasive and is preferred where the
block is not template-driven.

**3. Evaluate CDN self-hosting and Subresource Integrity.** 32 tags, no SRI.
Self-hosting removes the third-party hosts from `script-src` entirely and is
the strongest option. If they stay remote, add `integrity` plus `crossorigin`
and pin exact versions — the unversioned `chart.js` tag must be resolved to a
pin either way.

`cdnjs.cloudflare.com` appears in `script-src` but is never loaded as a
script: 22 templates pull Font Awesome 6.4.0 and animate.css 4.1.1 from it as
stylesheets, which `style-src` governs. The `script-src` entry is therefore
removable today.

**4. Add tests for the CSP response header and the intended script-loading
policy.** None exist today, so a header change is currently unobservable to
CI. Add at minimum: the header is present on a normal response, `script-src`
does not regress to a weaker value, and the set of inline scripts/handlers
does not grow. Reuse the filesystem-driven discovery approach from
`tests/test_xss_f35.py` — a hand-written file list is what let 38 live sinks
through during F34.

**5. Keep the existing template-script syntax tests and XSS regression suites
active throughout.** `tests/template_script_syntax.py` (driven by
`test_xss_f21.py`, `test_xss_f21_browser.py`, `test_xss_f35_browser.py`) and
the F35/F39/F41 suites must stay green through every step. They are the safety
net for the migration, not an obstacle to it.

**6. Roll out incrementally, preserving behaviour.** Do not ship a stricter
policy to production in one step. A nonce rollout that misses one inline block
breaks that page's JavaScript outright — the failure mode is a dead page, not
a warning. Sequence: convert handlers → extract scripts → add the header tests
→ enforce `script-src` without `'unsafe-inline'` under
`Content-Security-Policy-Report-Only` → observe violations → enforce.

**7. Remove `script-src 'unsafe-inline'` — only after items 1–6.** This is the
goal, and it is the last step, not the first. It must not be attempted while
any earlier item is outstanding, because the policy is what currently makes
the app function; tightening it early turns the migration's mistakes into
outages instead of report-only noise.

### Not yet scheduled

- `style-src` also carries `'unsafe-inline'` (Tailwind's runtime engine needs
  it). Same class of problem, larger surface. The third-party stylesheets —
  Font Awesome 6.4.0 and animate.css 4.1.1 from `cdnjs.cloudflare.com`, 22
  templates — also load without SRI, so the same self-hosting or
  `integrity` decision applies to `style-src`.
- No `Trusted Types` (`require-trusted-types-for 'script'`), which would make
  item 1's remaining DOM sinks structurally impossible rather than
  individually fixed.
- No `report-uri` / `report-to`, so violations are not currently collected.

## Residual DOM/XSS limitations

Recorded honestly. These are known and accepted, not fixed.

**Per-line text detection cannot see interpolations spanning multiple lines.**
The static sink scanner in `tests/test_xss_f35.py` reads templates line by
line, so an untrusted value interpolated into element text that wraps across
lines is not matched by the textual rule. A whole-file scan was rejected
because render code inside `<script>` blocks produced false positives. The
compensation is execution-based coverage in
`tests/test_xss_f35_browser.py`, which renders through the real path and
inspects the resulting DOM. The limitation is asserted as a recorded fact in
`test_multiline_text_runs_are_a_recorded_limitation` — if that test starts
failing, the detector's coverage has changed and the note is stale.

**Seven hand-rolled duplicate escaping helpers remain.** Tracked in
`KNOWN_DUPLICATE_ESCAPERS` in `tests/test_xss_f35.py`:
`activity-feed.js`, `movies-page.js`, `my-services.js`, `notifications.js`,
`suggested-follows.js`, `tv-shows.js`, `where-to-watch.js`. Four other files
(`chrome.js`, `more-like-this.js`, `tv-seasons.js`, `tv-tracker.js`) were
consolidated to delegating shims during F38. The seven are still hand-rolled
and can drift from the shared helper.

**`escapeText(null)` behaviour is unpinned.** The null guard is present and
correct; no test asserts the result. Mutation-testing confirmed that removing
it renders the inert literal text `"null"` rather than anything executable.

## Separate product issue: list-cover file upload is broken

**This is not a CSP finding.** Do not file it under security.

`static/js/list-enhancements.js` offers a cover-image upload that posts a
`data:` URL. It cannot succeed:

- The F39 policy rejects `data:` URLs.
- `cover_image` is `db.String(500)`; a `FileReader.readAsDataURL` payload
  exceeds that for any real image.
- The F38 renderer refuses `data:` URLs.

CSP is not the blocker — `img-src` permits `data:`, so the browser would render
one if it reached the DOM. The path is already broken independently of policy.

It was reported rather than half-fixed: accepting `data:` URLs would need a
storage design (an upload endpoint, or blob/object storage with a URL written
back), not a validation change. **Open decision: give the UI a real upload
target, or remove it.**

## Re-verifying the counts

The inventory above is a snapshot, not a fact to trust. Recompute it before
relying on it — and update this file in the same commit if it has moved.

Rules used, so the numbers are reproducible:

| Item | Rule |
|---|---|
| Inline `<script>` | `<script` opening tag with no `src=` attribute, in `templates/*.html` |
| Inline handler | `on<name>=` on an HTML tag, after stripping HTML comments, `{# #}` comments and `<script>` block contents |
| JS-generated handler | `on<name>=` inside `<script>` block bodies or `static/js/*.js`, after stripping block, line and jsdoc comments |
| CDN without SRI | `<script src>` whose URL is absolute and whose tag has no `integrity=`, in `templates/*.html` |
| Duplicate escapers | Read `KNOWN_DUPLICATE_ESCAPERS` from `tests/test_xss_f35.py` — never hard-code the list |
| CSP tests | `grep -rl "Content-Security-Policy\|script-src" tests/` |

Note that the earlier working figures for items 1–4 (42 / 96 / 17 / 27) were
taken before F38–F41 and used looser rules that counted commented-out handler
examples and some script-block contents. The counts here were produced by two
independent methods that agree, and are the ones to use.
